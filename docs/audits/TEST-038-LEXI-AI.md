## 5. Cloudflare Worker

- **AI API:** Anthropic Messages, структурований JSON (`output_config.format`), тайм-аут 25 с (менше за 30 с у застосунку). Відмова моделі (refusal) і зламаний JSON дають окремі коди; рушій і UI їх розрізняють (виправлення №2).
- **Ключі:** лише в змінних середовища Worker, не потрапляють у відповіді. IP і код пристрою зберігаються тільки як HMAC.
- **Ліміти:** за хвилину (пристрій / мережа / усі), за день (пристрій / мережа) з поверненням ліміту, якщо відповідь не дійшла; є аварійний вимикач `AI_OFF`.
- **CSP:** застосунок звертається лише до `'self'`; тестовий AI працює через локальний проксі.
- **Відповідність контракту Lexi:** усі коди помилок Worker тепер відповідають `LerenLexi.ERRORS` і `errorPolicy` в `copy.js` Codex (12 кодів, прапорці повтору збігаються). Нових методів для UI не потрібно.
- **Firebase App Check — немає.**
  - Застосунок отримує токен App Check лише для Firestore (`appCheckHeaders`, `app.js:5817`). AI-запити його не надсилають, і Worker його не перевіряє.
  - Захист AI зараз: Origin (підробляється поза браузером), ліміти, ліміт витрат workspace.
  - **Пропозиція** (потребує погодження, бо змінює production Firebase / Cloudflare і контракт):
    1. клієнт надсилає `X-Firebase-AppCheck` лише на lerenbe.com;
    2. Worker перевіряє JWT за JWKS Firebase;
    3. спершу режим «лише журнал» (`APPCHECK=report`), потім `enforce`.
  - Тестовий Worker можна перевірити першим.
- **Тестова конфігурація:** `tools/lexi-test-worker.toml` (`leren-ai-test`, окремі KV, сіль, ключ, origin лише `localhost:8765`, нижчі ліміти, `AI_OFF=1` після кожного розгортання). Підготовлено в TEST-034, перевірено `lexi-test-worker.cjs`. **Не розгорнуто.**

- Чи модель повертає `learner_in_target`, `severity` і `correction` так, як очікує Worker (структурований вивід перевірено лише формою).
- Реальні затримки й частоту тайм-аутів; реальну поведінку refusal.
- Роботу лімітів Cloudflare (bindings `PER_IP`, `IP_CEIL`, `ALL`) і KV у мережі Cloudflare.
- App Check (його поки немає).
- Порядок: тестовий Worker за `docs/LEXI-TEST-WORKER.md` → після окремого погодження.

## 7. Що перевірити на Samsung (`docs/SAMSUNG-LEXI-TEST.md`)

1. Перший запит мікрофона: дозвіл → розпізнавання nl-BE / fr-BE / en; відмова → повідомлення й текстовий режим.
2. Відмова «назавжди» в налаштуваннях Chrome → кнопка мікрофона не зависає, є текстовий ввід.
3. Android Chrome повторює слова в безперервному режимі: має працювати однократне розпізнавання з перезапуском (`listenLong`).
4. Довга фраза голосом (≈ 300 символів) у «Говорінні» → відповідь без службового тексту `[spoken …]`.
5. Питання в «Граматиці» голосом мовою інтерфейсу (uk-UA / ar-SA).
6. TTS: озвучення nl-BE / fr-BE / en; що робить телефон без голосу потрібної мови.
7. «Перекласти» в чаті при інтерфейсі en / fr / ar → переклад цією мовою.
8. Кнопка «Назад» Android, згортання під час розпізнавання, офлайн → «Ти офлайн».
9. TalkBack: стани «думає / помилка» оголошуються.

**На телефоні нічого не перевірено.**
